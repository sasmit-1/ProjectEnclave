Problem Statement and USP’s Problem Statement: Traditional cloud storage encrypts data "at rest," but once a user's credentials or session tokens are compromised, the storage provider willingly decrypts and serves the files to the attacker. Static Defenses: Standard vaults cannot distinguish between a legitimate user and an automated exfiltration script. The Ransomware Threat: Attackers bypass perimeter security by stealing authenticated sessions. Mass Exfiltration: Without behavioral monitoring at the application layer, gigabytes of sensitive data can be drained in minutes. USP’s: Active  Behavioral   Defense : An autonomous monitoring engine that tracks download velocity and instantly terminates sessions, severing active TCP streams if script-like data extraction is detected. ​Zero-Overhead Streaming Encryption: Utilizes constant-memory stream chunking to encrypt and decrypt multi-gigabyte files on the fly, completely bypassing server RAM limitations. ​Cryptographic Integrity Validation: Employs AES-256-GCM authenticated encryption. Any tampering by ransomware in the storage layer is immediately flagged and rejected via authentication tag failure.

Tech-Stack Frontend (Client & UI) ​React + Vite: For lighting-fast hot module replacement and component rendering. ​Tailwind CSS: For building the high-contrast, AMOLED black UI with minimalist precision. ​HTML5 Canvas API / Framer Motion: To render the real-time visualizers showing the mathematical chunking and encryption processes during file uploads. ​ Zustand : For lightweight, fast global state management (managing authentication state and active upload streams). ​Backend (Server & Cryptography) ​Node.js (Node Streams API): You will rely heavily on  fs.createReadStream (),  fs.createWriteStream (), and stream/promises (pipeline) to pipe data without holding it in RAM. ​Express.js: To handle the API routing and WebSocket/Server-Sent-Events connections for the active defense logs. ​Node Built-in crypto: Specifically using  crypto.createCipheriv ('aes-256-gcm', key, iv) to offload the heavy cryptographic lifting to the underlying C++ OpenSSL bindings. ​Redis: This is mandatory. You cannot query MongoDB fast enough to stop an attack mid-stream. Redis will sit in the backend RAM to track high-speed download velocities and immediately invalidate sessions. ​Database & Storage ​MongoDB (Mongoose): To store user metadata, file folder hierarchies, and—crucially—the cryptographic Nonces (IVs) and Authentication Tags required to decrypt the files later. ​AWS S3 (or Local File System): To store the actual encrypted ciphertext binary blobs.
